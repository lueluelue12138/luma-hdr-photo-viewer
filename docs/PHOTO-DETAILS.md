# 照片信息侧栏

Luma 0.1.22 在顶部悬浮工具栏增加独立信息入口，快捷键 `I` / `Ctrl+I`；关闭按钮和 `Esc` 可收起。侧栏与工具栏共用现有主题 / 原生渲染玻璃，窄窗口可滚动，打开时缩略图栏让出右侧位置。

常用信息优先展示：文件名、完整路径、字节大小、像素 / MP、系统报告的 dpi 和位数、拍摄 / 文件修改 / 创建时间、相机、镜头、焦距、f-number、快门、ISO、曝光补偿、EXIF 色彩空间、实际解码的 HDR 来源，以及当前查看状态。含有效 GPS 时显示经纬度；只在本机读取，不查询在线地理服务。

其他参数按相机与镜头、曝光、图像、其他分组，可搜索名称、值及属性标识。包括等效焦距、数字变焦、测光、白平衡、闪光、曝光程序、方向、锐度、饱和度、软件、版权、作者、关键词、评分和 EXIF 版本等；仅显示系统实际返回的字段，缺失不会继承前一张照片。零曝光补偿 / 自动白平衡保留，非有限或无效量值不伪装为拍摄参数。复制路径、复制完整详情、打开原文件位置三个操作保持相同行高和圆角。

通过 [Windows 图像元数据接口](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/image-metadata) 和 [Windows Photo 属性](https://learn.microsoft.com/en-us/windows/win32/properties/photo-bumper) 读取，复用已安装的系统格式处理器。f-number 与 APEX 光圈值分开命名；快门用秒或倒数，曝光偏移用 EV。文件创建时间不冒充拍摄时间。EXIF 色彩空间不是 ICC 描述，未标定不代表没有宽色域配置；[系统 BitDepth](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-image-bitdepth) 为每像素位数，也不作为 HDR 检测依据。源 HDR 类型来自已成功解码的帧，当前显示状态独立。

仅在打开侧栏后读取，文件访问与系统属性操作放在后台；并发上限 2，按规范化路径、大小和修改时间保留最多 64 份小型元数据记录。切换、收起和关闭取消旧请求，回到 UI 时再核对当前照片 / 请求代次。不会因图库有几千张照片就预读取全部 EXIF，也不向 Luma 解码器或 NVIDIA 发送额外处理任务。照片像素缓存预算不变，未新增运行时依赖。

本轮为只读详情，不改写原图。改名、修改拍摄日期、调整图像尺寸、视觉搜索和完整 ICC 描述不在此次已实现范围，后续见 [TODO](TODO.md)。搜索框输入遵循文本编辑行为，避免 `I` / `R` / 方向键误触发看图操作；普通按钮、缩略图及其他控件的空格原图对照继续优先。

验证入口：`tests/verify_photo_details.py --app <消费者程序> --photo <可选的真实照片>`，使用隔离测试库。脚本生成 EXIF / GPS 图并核对系统读取、缺失参数、HEIC、增益图、缓存、并发翻图、窗口边界及读取中关闭。`--verify-photo-details` 仅在 `--test-library` 下启用。XAML 检查图使用临时中性底色查看文字 / 布局，不能当作真实毛玻璃或 HDR 观感证据；截图、原照片与日志都留在忽略的本机 QA 目录。
